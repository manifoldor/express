## 2. 单号智能识别算法 (Carrier Auto-Detection)

当用户未显式指定快递公司时，系统先基于正则和特征加权算法进行本地快速推导；同时支持回退至在线自动探测接口。

### 2.1 识别流程
```text
用户输入单号 ───> 正则规则库初筛 ───> 匹配度权重打分 ───> 输出置信候选
      │
      └─ 若单号无明显特征 ───> 在线探测 API ───> 确定快递公司
```

### 2.2 置信度分级
- **HIGH**：具备强前缀特征（如 `SF...`, `YT...`, `JD...`, `JT...`, `EA...CN`）。
- **MEDIUM**：符合典型号段长度与开头数字分布（如中通 `75...` 12位、韵达 `43...` 13位）。
- **LOW**：仅符合通用位数特征，需要列出所有候选或借助接口探测。

## 3. 标准化物流状态机 (Status Machine)

无论底层数据源来自快递100、快递鸟还是各家直连接口，系统均将状态归一化为如下 7 大标准状态：

```text
[PENDING] 待揽件
    │
    ▼
[PICKED_UP] 已揽收
    │
    ▼
[IN_TRANSIT] 运输中 / 转运中
    │
    ▼
[OUT_FOR_DELIVERY] 派送中
    │
    ▼
[DELIVERED] 已签收
    │
    ├──> [EXCEPTION] 异常（拒收/退回/滞留/破损）
    └──> [EXPIRED] 超期未更新
```

每个节点包含：
- `time`: 标准时间戳（`YYYY-MM-DD HH:mm:ss`）
- `context`: 详细轨迹文本（如：“[北京市] 快件已到达 北京海淀转运中心”）
- `location`: 结构化地理位置（省份、城市、区县、网点）
- `status`: 标准化状态枚举
- `courier`: 派件员姓名（如有）
- `courierPhone`: 派件员或网点联系电话（如有）

## 4. 监控跟踪清单 (Watchlist & Polling)

支持对包裹进行持续关注与追踪：
1. **添加关注 (`express_add_watchlist`)**：添加单号、快递公司、自定义备注（如：“买的新键盘”、“寄给客户的合同”）。
2. **状态轮询 (`express_poll_updates`)**：
   - 比较上次记录的最新时间戳与最新节点哈希。
   - 检测是否有新状态产生（例如：从运输中变为派送中、从派件中变为已签收）。
   - 产生高优先级提醒事件推送。
3. **数据持久化**：存储在本地 `~/.grokbot/express/watchlist.json`，重启不丢失。

## 5. 多源查询与沙箱回退保障

1. **企业商业 API**：
   - 配置 `KUAIDI100_KEY` & `KUAIDI100_CUSTOMER` 时优先走快递100云接口。
   - 配置 `KDNIAO_API_KEY` & `KDNIAO_E_BUSINESS_ID` 时启用快递鸟即时查询。
2. **开放接口与无密回退**：
   - 支持主流平台公开轻量接口查询。
3. **内置物流沙箱仿真器 (Simulator)**：
   - 当在无外网 API 凭证或开发调试场景下，自动启动物流轨迹仿真器。
   - 能够基于真实的中国城市物流路由（如：深圳 -> 武汉 -> 北京 -> 海淀区中关村网点）生成符合物理规律的真实轨迹模拟数据，保障 Agent 体验不中断。
