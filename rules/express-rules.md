# 快递物流交互约束规范

在处理快递查询、解析物流数据及生成向用户展示的内容时，必须遵守以下准则：

1. **状态归一化规范**：
   - 必须统一转换为系统标准的 7 种状态之一：`PENDING`（待揽收）、`PICKED_UP`（已揽收）、`IN_TRANSIT`（运输中）、`OUT_FOR_DELIVERY`（派送中）、`DELIVERED`（已签收）、`EXCEPTION`（异常件）、`EXPIRED`（超期未更新）。
   - 杜绝将外部各服务商生僻状态直接抛给用户，必须提供易懂的中文状态标签。

2. **时间线呈现顺序**：
   - 默认展示物流轨迹时，**必须按时间倒序（最新的节点排在最上方）**展示，方便用户第一时间获知最新进度。
   - 关键字段必须高亮：最新所在网点、更新时间、派件员联系电话。

3. **隐私与敏感信息保护**：
   - 物流轨迹中涉及收件人真实姓名或模糊地址时，应保持原有脱敏处理（例如：`张*先生`、`北京市海淀区**小区`）。
   - 派件员电话和网点联系电话应清晰保留，以便用户需要时能够一键拨打催件或改约送货时间。

4. **异常件主动指引**：
   - 当遇到包裹拦截、收件人不在、拒收、地址错误等异常状态时，不得仅输出状态，必须附带该快递公司的官方服务电话或申诉/催派建议。
